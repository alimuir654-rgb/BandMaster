# Mandatory check before every work session

**Goal: reproduce the quality and visual language of the owner-approved mockups in usable native components. Do not lower the target to the current implementation.**

1. **Authority and continuity.** Read the latest owner request, AGENTS.md and the compact output of `python3 tools/project_context.py start`; follow its active session/evidence pointers. Read only relevant ledger entries. Confirm branch/head and exclusive writer. Historical queues/deadlines do not override a newer direct request; a new request is not permission to merge or alter saves.
2. **Lessons and recurrence.** Read the relevant LESSONS.md sections with `project_context.py lessons --ids ...` (`--full` for task-specific extensions) and every new ISSUES.jsonl event since the last verified review cursor with `project_context.py issues`. Full policy/history hashes remain machine-checked; the reader never advances the reviewed cursor. Select the relevant lesson IDs, the single dominant issue and its prevention checks. Do not repeat failed methods or restart completed work.
3. **Target and baseline.** Actually open the relevant mockup and latest native failure. Pin original reference identity/hash, baseline code and source assets. A textual target alone is not evidence of viewed reference pixels; record a blocker when a required source is absent.
4. **Reuse and safety.** Inventory existing assets/APIs first. Confirm true source type, rights, dimensions, complete dependencies and canonical data. List protected art/logic/saves. Keep mockup composites out of production textures.
5. **Controlled hypothesis.** State exactly what should visibly improve and why. Keep A/B content, viewport, state, background and frame bounds constant. Define what would count as regression and the method-change/stop condition.
6. **Commit preflight before implementation.** Create/update a scoped session with current document hashes, the reviewed issue-log prefix, target, baseline, paths and tests. Run `python3 tools/improvement_gate.py check --session docs/continuous_improvement/sessions/<ID>.json`. The record must be committed before code/art changes. Do not tick without evidence.
7. **Execute and inspect.** Implement, run clean import/behaviour tests, render native 390x844/720x1280/1280x720/1600x900, open original PNGs, compare to the mockup and baseline. Keep technical, visual and owner gates separate. Do not alter tests/goldens to disguise defects.
8. **Log immediately.** On every new failure or recurrence, append an event to ISSUES.jsonl BEFORE the next implementation iteration; give expected/observed, evidence, severity, cause confidence, corrective action, prevention and verification. Reuse existing lesson IDs. Two ineffective attempts require a changed method or explicit hold.
9. **Close honestly.** Record exact files, tested SHA/run/artifact, images opened, remaining gaps, five simulated review lenses and ONE next action; update the compact current records, queue, handover and relevant ledger entry, run `python3 tools/project_context.py check`, and release the writer. Keep `owner_approved=false` unless the owner explicitly approves the specific result. No automatic extension or merge.

## Enforcement boundary
The gate validates a current, scoped, source-linked record and append-only issue history. It cannot prove someone read an image or automatically judge artistic quality. Native pixel inspection and owner acceptance remain separate. CI cannot prevent a local edit, and branch-protection settings are not changed by this policy.

## UI/UX review points

Before development, an independent reviewer inspects the actual reference/current assets and complete player flow, then pins a few visible acceptance conditions. At the first working native composition, review phone and short landscape before full integration/proof; HOLD concrete clipping, unreadable controls, hidden decision context or incoherent hierarchy. After development, compare matching exact-source states against both the intended target and prior verified layout, then review the complete journey and corrections. Keep one implementation writer; controls/layout reviewers use explicitly scoped scratch evidence and verify fixes. Reviewers report prioritised evidenced defects, not decorative tweak lists. Technical checks, internal visual acceptance and owner approval remain separate; simulated lenses are not human testing. APK work remains held by latest owner direction.

Use the **current tables in S80_EXECUTION_QUEUE.md** as the single artwork and controls/layout worklist. Assign an existing helper to the role and record its current task, status, evidence and closure decision; a role is not a continuous background service. Limit work in progress to one shipping integration, one asset job/version and one complete player-task review. Do not rebuild a screen merely because it appears on a review list. A demonstrated art blocker does not block unrelated approved layout or written-experience work.

The active session records the queue task ID, reviewer, player goal/start/end/commitment point, important beats/interruptions, actual reference/current originals, controlled hypothesis, visible acceptance and disposition. Pin a small risk-based state matrix: selected/focused/disabled, long names/glyphs, empty/held/error/retry, scrolling/focus/modals, dirty exits, Menu/resume/reload, normal/reduced motion and actual physical targets/contrast. Early review covers important task states, not just the opening frame. Preserve existing control/type/material rules and source-backed dialogue; do not shrink text or redesign protected components to achieve consistency.

HOLD inaccessible essential context/actions, unreadable content, false local/saved/current meaning, unsafe modal/dirty-data behaviour or save/once regression. Treat other evidenced composition limits as scoped P2 repairs with explicit closure, and optional decoration as lower priority. Use actual owner feedback when received; automated task completion and SIMULATED lenses do not prove human comprehension. The record gate validates records, not image viewing or artistic quality; these additional review fields are procedural requirements, not a claim of new automated enforcement.

Before multi-path source reads, select paths from the current curated manifest or actual rg --files inventory and check that every path exists. Never guess controller names. Reuse exact unchanged proof honestly and reserve storage for the complete remaining journey and closeout; no unchanged suite/import/APK reruns for activity.

For audio work, inspect the latest owner-authorised audio session and its source/listening gates; historical AU01 instructions are archived with this policy. No audio acquisition/integration, paid credits, new dependencies or APK work is added by the current presentation/continuity pass. Dummy-audio QA is not a listening test.

## Compact continuity

Keep current records small and authoritative; preserve old bytes in the history manifest. One pass has one current task and next action. Checkpoint at meaningful boundaries and complete the handover before starting another milestone. The context reader prints selected state/lessons and verified issue deltas; inspect full historical records only to resolve a concrete question. The context check supplements, and never replaces, the existing preflight/history gate or native visual review.
